# Бот для P2P CryptoBot

Следит за стаканами P2P в @CryptoBot и присылает в Telegram сигналы, когда твоё объявление перебили. Курс можно поменять одной кнопкой прямо из сигнала. Ещё бот ведёт историю сделок мерчантов и считает, как часто они меняют курс.

## Что умеет

- **Сигнал о перебивке.** Если в твоей лимитке кто-то встал выше, приходит сигнал: кто первый, кто прямо над тобой и какой курс поставить. Лимитка — это объявления с тем же **минимальным** лимитом, максимальный не важен. Курс в сигнале нажимается и копируется. Повторный сигнал приходит, только если что-то поменялось. Когда ты снова первый, приходит «👑 Снова первый».
- **Кнопки под сигналом.** «✅ Да, встать первым» и «⬆️ На одного». Бот сам меняет курс объявления и проверяет по стакану, что курс действительно поменялся. Кнопка живёт 5 минут.
- **Два бота сигналов.** Один — для USDT к валютам (USDT/UAH, USDT/KZT…), второй — для монет (BTC, ETH, TON…).
- **Отключение сигналов по рынку, монете или валюте** командами `/mute` и `/unmute`.
- **Любые валюты и монеты, фиксированная и плавающая цена.** Шаг перебивки подбирается под рынок (см. ниже).
- **История сделок.** Сделка определяется по уменьшению объёма объявления. Когда у мерчанта растёт счётчик сделок, сделка помечается ✅.
- **Смены курса у мерчантов** за последние 10 минут (`/prices`).
- **Запасные наблюдатели.** Если аккаунт-наблюдатель завис или его заблокировали, бот сам переходит на следующий и присылает уведомление.
- **Прокси для наблюдателей** (необязательно).

## Как устроено

| Кто | Что делает |
|---|---|
| **Наблюдатели** (2–3 аккаунта Telegram) | Через мини-приложение CryptoBot читают стаканы каждые ~5–7 сек. Работает один, остальные в запасе. Свои объявления не нужны. |
| **Перебивающий** (основной аккаунт с объявлениями) | Стаканы **не читает**. Только меняет курс, когда ты нажал кнопку в сигнале. Меняет через обычный диалог в чате @CryptoBot (`/p2p → Объявления → объявление → Цена → курс → Сохранить`) с человеческими паузами. Для CryptoBot это выглядит как нажатия с телефона. Одна смена занимает ~30 сек. |
| **Боты сигналов** (2 бота от @BotFather) | Присылают сигналы, принимают команды и нажатия кнопок. |

## Установка

1. Установить Python 3.10 или новее с [python.org](https://www.python.org/downloads/). При установке поставить галочку **«Add Python to PATH»**.
2. Запустить `install.bat`, он поставит нужные библиотеки.

## Настройка (один раз)

Все настройки находятся в файле **`config.py`**. Его можно открыть Блокнотом.

### 1. Боты сигналов

1. В Telegram открой @BotFather → `/newbot`. Создай двух ботов, например «мои сигналы USDT» и «мои сигналы монеты».
2. Токены вставь в `config.py`:
   ```python
   SIGNAL_BOTS = {
       "usdt":  "123456:AAAA...",   # USDT к валютам
       "coins": "654321:BBBB...",   # остальные монеты
   }
   ```
   Можно обойтись одним ботом: если оставить `"coins": ""`, сигналы по монетам придут в первый бот.
3. Желательно указать свой Telegram ID (его можно узнать у @userinfobot): `ADMIN_IDS = [123456789]`. Тогда ботом сможешь командовать только ты. Если оставить пустым, хозяином бота станет тот, кто первым напишет ему `/start`. В этом случае напиши `/start` сам сразу после первого запуска.

### 2. Ник

```python
MY_NICKNAME = "Juice_p2p"   # как твои объявления видны в стакане
```

### 3. Аккаунты

Для каждого аккаунта один раз запусти вход по QR-коду:

```
python qr_login.py observer1
python qr_login.py observer2
python qr_login.py observer3
python qr_login.py trader        ← основной аккаунт с объявлениями
```

В браузере откроется QR-код. Отсканируй его с телефона **из Telegram** нужного аккаунта: Настройки → Устройства → Подключить устройство. Если на аккаунте стоит облачный пароль, скрипт спросит его. При вводе символы не видны, так и должно быть. После входа рядом появится файл `observer1.session` и т.д.

В `config.py`:
```python
OBSERVER_SESSIONS = ["observer1", "observer2", "observer3"]
TRADER_SESSION = "trader"
```

Проверить, что аккаунт видит стаканы: `python check_app.py observer1`.

> ⚠️ **Файл `.session` даёт полный доступ к аккаунту.** Никому его не пересылай. Если файл утёк, в Telegram зайди в Настройки → Устройства и заверши этот сеанс.

### 4. Рынки

```python
MARKETS = {
    "USDT/UAH": {"limits": [2000, 3000, 5000, 8000]},
    "USDT/KZT": {"limits": [200000, 500000]},
    "BTC/UAH":  {"poll": 20},
    ...
}
```

Рынок записывается как `"МОНЕТА/ВАЛЮТА"`. Внутри всё необязательно:

| Параметр | Что значит |
|---|---|
| `limits` | минимальные лимиты, для которых на экране показывать лидера |
| `side` | `"sell"` — стакан с объявлениями «Покупка» (вкладка «Продать»), `"buy"` — наоборот. Если не задан, бот сам найдёт, где стоят твои объявления |
| `step` | шаг перебивки фиксированной цены |
| `pct_step` | шаг перебивки плавающей цены, в процентных пунктах (по умолчанию 0.01) |
| `poll` | как часто опрашивать именно этот рынок, сек |
| `max_jump` | свой предел скачка курса для кнопок |
| `bot` | `"usdt"` / `"coins"`, если нужно отправлять сигналы не туда, куда по умолчанию |
| `enabled` | `False` — не опрашивать рынок совсем |

**Каждый рынок — это лишние запросы к CryptoBot**, поэтому добавляй только те, где торгуешь. Монеты стоит опрашивать реже (`"poll": 20`).

### 5. Запуск

Запусти `start.bat`. Если бот упадёт, он перезапустится сам через 15 секунд. Потом напиши `/start` **каждому** боту сигналов.

## Команды ботов сигналов

| Команда | Что делает |
|---|---|
| `/status` | где тебя перебили и какой курс ставить |
| `/markets` | рынки этого бота: 🔔 сигналы идут, 🔕 заглушены |
| `/mute BTC` | не присылать сигналы по BTC. Можно указать рынок `BTC/UAH`, монету `BTC` или валюту `KZT` (тогда заглушатся все рынки с KZT) |
| `/unmute BTC`, `/unmute all` | снова присылать сигналы |
| `/deals` | последние сделки (✅ — подтверждена счётчиком сделок мерчанта) |
| `/prices` | кто сколько раз менял курс за 10 минут |
| `/clear`, `/clear USDT/UAH`, `/clear Ник` | забыть запомненные объёмы, например после сбоя |

Заглушённые рынки бот продолжает опрашивать: они видны на экране и в `/status`, просто сигналы по ним не приходят. Что заглушено, хранится в `settings.json` и сохраняется после перезапуска. Начальный список задаётся в `MUTED` в `config.py`.

## Шаг перебивки

Бот ставит курс на один шаг лучше конкурента. «Лучше» — значит выше в стакане «Покупка» и ниже в стакане «Продажа». Шаг бот выбирает сам, по тому, как мерчанты ставят курс на каждом рынке:

| Рынок | Как ставят курс | Шаг бота |
|---|---|---|
| USDT/UAH, USDT/KZT, USDT/RUB и др. | 2 знака после запятой (45.67) | 0.01 |
| USDT/USD, USDT/EUR (курс около 1) | 4 знака (0.8776) | 0.0001 |
| любой рынок с курсом меньше 10 | — | 0.0001 |
| монеты (BTC, ETH, TON, TRX, SOL, LTC, DOGE) | почти всегда **плавающая** цена (−5.7% от биржевого) | 0.01 процентного пункта |

Если у конкурента курс точнее твоего шага (например, 45.675), бот всё равно ставит ровно на один шаг лучше (45.68). Свой шаг можно задать параметром `step` или `pct_step` у рынка.

**Плавающая цена.** Если у твоего объявления плавающая цена, бот меняет процент, а не курс. Например, «−5.49%» вместо «−5.7%». Это работает и против конкурента с фиксированной ценой: бот пересчитает его курс в процент от биржевого. Тип цены (фиксированная или плавающая) бот не переключает.

### Защита от ошибок

- **Скачок больше `MAX_JUMP_PCT`** (по умолчанию 1%; у плавающей цены — 1 процентный пункт): курс не меняется. Бот пишет «поменяй вручную» и даёт курс для копирования. Так случайный кривой курс конкурента не утащит твой курс.
- **Перед сменой** бот заново читает стакан: с момента сигнала всё могло сдвинуться.
- **Если CryptoBot ответил не так, как ожидалось** (другие кнопки, отказ, другая цена после сохранения), бот останавливается и присылает «❌ курс не изменён» с текстом экрана. Наугад он ничего не нажимает.
- **Ограничения CryptoBot:** курс должен быть в пределах ±50% от биржевого (USD — ±15%, TON — ±70%). Если CryptoBot когда-нибудь введёт паузу между сменами курса, бот покажет его ответ.

## Прокси для наблюдателей (необязательно)

Без прокси все аккаунты работают с одного IP. Его видят и Telegram, и CryptoBot, поэтому по IP наблюдателей можно связать с основным аккаунтом. Чтобы этого не было, дай наблюдателям свои прокси:

```python
OBSERVER_PROXIES = {
    "observer1": "socks5://логин:пароль@1.2.3.4:1080",
    "observer2": "http://5.6.7.8:3128",
}
```

Через прокси идут и вход по QR (`qr_login.py`), и Telegram, и запросы к CryptoBot. Подходят socks5, socks4 и http. Основной аккаунт `trader` работает без прокси, как обычный телефон.

## Что видит CryptoBot

- **Основной аккаунт** только пишет и нажимает кнопки в чате. Боты в Telegram не знают, с какого устройства пришло нажатие, поэтому это неотличимо от телефона. Заметить можно только поведение: быстрая реакция на перебивку, шаг всегда 0.01. Курс меняется только по твоей кнопке.
- **Наблюдатели** открывают мини-приложение и часто запрашивают стаканы. Это самое заметное место, поэтому наблюдателей несколько.
- В Telegram → Настройки → Устройства у каждого аккаунта появится отдельный сеанс бота.

## Если что-то сломалось

- **«❌ Диалог с CryptoBot пошёл не так»**: скорее всего, CryptoBot поменял кнопки в чате. Запусти `python record_flow.py trader` и поменяй курс вручную в чате @CryptoBot. Курс можно поставить тот же. Потом нажми Ctrl+C и пришли разработчику `flow_log.txt`: там только тексты экранов бота.
- **«CryptoBot не отвечает 5 раз подряд»**: временный сбой CryptoBot или прокси. Бот сам сделает паузу (до 2 минут) и продолжит.
- **«🔁 Наблюдатель … сбоит»**: бот перешёл на запасного наблюдателя. Проверь аккаунт: `python check_app.py observer1`.
- **«Перебивающий аккаунт недоступен»**: сессия `trader` не входит. Запусти `python qr_login.py trader` заново.
- **Не приходят сигналы**: напиши боту `/start`; проверь `/markets`, не заглушён ли рынок; проверь, видит ли бот твоё объявление (`/status`).
- **После долгого простоя** бот не берёт старую память объёмов (старше 15 минут), чтобы не показать все продажи за это время пачкой «сделок».

Бот читает внутреннее API мини-приложения CryptoBot. Это не публичный интерфейс, и при обновлении CryptoBot его могут поменять. Тогда понадобится доработка.

Почему бот устроен именно так (API, разделение аккаунтов, шаги перебивки) — в [DECISIONS.md](DECISIONS.md).
