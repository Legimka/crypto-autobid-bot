# Модули перебивки CryptoBot

Два модуля торговли на CryptoBot. Оба — автоперебивка: встать на шаг «лучше» ближайшего конкурента
в пределах коридора. xRocket — отдельно, позже.

## Откуда логика

| Модуль | Источник | Как читает стакан | Как меняет цену |
|---|---|---|---|
| `autobid/cryptobot/p2p.py` | `cryptobot-p2p-bot/stakan.py` (новее старого бота) | внутренний API мини-приложения (`app_api.py`) | API (`app_api.set_price`) или диалог в чате (`chat_trader.py`) |
| `autobid/cryptobot/exchange.py` | `old_bot_p2p` (декомпиляция `Cryptobot 1.6.7`) | клики по кнопкам в чате `/exchange` | клики по кнопкам в чате |
| `autobid/cryptobot/outbid.py` | общая чистая математика (из обоих) | — | — |

У P2P и у биржи CryptoBot **нет публичного API**. P2P удалось перевести на внутренний API мини-приложения
(быстро, надёжно). Биржа осталась на кликах по кнопкам, как в старом боте.

## Общая математика — `outbid.py`

Чистые функции (без сети), на них тесты `tests/test_outbid.py`:

- `step_for(price, step)` — шаг сетки цены (0.0001 для курса < 10, иначе 0.01, либо явный).
- `beat(value, step, asc)` — ближайшее значение на сетке, строго лучшее конкурента.
- `fixed_target` / `floating_target` — куда переставить фиксированную / плавающую цену; с **коридором**:
  если перебить = выйти за `max_dev_pct` от исходного курса, возвращаемся к исходному (`reset=True`) — как в ТЗ.
- `exchange_target` — цель для биржи (`enemy ± step` в пределах `limit`), формула из старого бота.
- `allowed_jump` — защита от аномалий: не прыгать больше `max_jump` за правку.

## P2P — `p2p.py`

`P2POutbidder` на одну пару. Проход (`step_once`): прочитать стакан → для каждого своего объявления найти
лидера в своей **минимальной лимитке** → посчитать курс (`outbid.fixed/floating_target`) → проверки
(коридор, `max_jump`, частота правок) → сменить курс.

- Соревнуемся только внутри своего минимального лимита (в CryptoBot покупатели фильтруют по нему).
- `CooldownGuard` — не больше N правок одного объявления, потом пауза (перенос из `changeOrder.py` старого бота).
- `trader_mode="app"` — курс меняется запросом к API (быстро); `"chat"` — диалогом в чате (с паузами, «как человек»).
- `build(market_key, cfg)` поднимает клиентов наблюдателя/перебивающего из настроек рынка.

## Биржа — `exchange.py`

`ExchangeTrader` на одну пару. Заходит в `/exchange`, выбирает пару, читает стакан (кнопки-ордера с 🟢/🔴,
свой помечен 🔸), решает (`decide`, чистая функция — есть тесты) и ставит/переставляет ордер. После
исполнения («Order #… executed successfully») «Покупка» переключается на «Продажу», «Продажа» — останавливает.

✅ **Сверено с оригинальным исходником.** Логика и позиции кнопок проверены по найденному исходнику
`cb_win-main` (`plugins/refresh/refreshExchangeNew.py`, `utils/handelPurchase.py`, `GUI/src/help-text.ts`):
движок биржи, карта кнопок и переход «покупка → продажа» после исполнения совпадают с нашим портом 1:1,
а схема конфига (аккаунт/пара/лимит/sell_limit/шаг/difference/объём/режим) — с подсказками GUI. Из раннего
варианта оригинала (`refreshExchange.py`) добавлена **устойчивая отмена своего ордера по тексту `📔`** с
откатом на позицию `(14,2)` — см. `_replace`.

Подтверждённая карта кнопок (для той версии интерфейса):

| Действие | Кнопки |
|---|---|
| Открыть биржу | `/exchange` → `(2,0)`→`(1,0)`→`(0,0)`→`(15,0)` → выбор пары по тексту |
| Читать стакан | все кнопки последнего сообщения; свой ордер `🔸`, покупки `🟢`, продажи `🔴` |
| Поставить ордер | `(14,1)` → вкладка `(0,0)`Buy/`(0,1)`Sell → `(0,1)` цена → отправить цену → `(0,0)` → объём или `(1,0)` → `(0,0)` |
| Отменить/переставить | `📔` (или `(14,2)`) → `(1,0)` → `(1,0)` |
| Исполнение | «Order #… executed successfully» → Buy→Sell (лимит = sell_limit), Sell → стоп |

> ⚠️ **Позиции кнопок соответствуют ТОЙ версии интерфейса CryptoBot**, под которую писался старый бот.
> Текущий CryptoBot мог поменять раскладку кнопок. **Перед боевым запуском проверь их по свежей записи:**
> `python record_chat.py test cryptobot -i`, пройди `/exchange` вручную и сверь номера кнопок в `chat.txt`.
> Решение (`decide`) от позиций не зависит и покрыто тестами, так что менять, скорее всего, придётся только
> константы навигации.

## Запуск и обвязка

Оркестратор `autobid/runner.py` (точка входа — `run.py` в корне) поднимает все **включённые** рынки из
`config.py` и держит их 24/7 (ТЗ §7):

```
python run.py            все рынки (P2P + биржа)
python run.py p2p        только P2P
python run.py exchange   только биржа
```

- **Изоляция и перезапуск.** Каждый рынок — отдельная задача. Падение одного не роняет остальные; после
  ошибки рынок перезапускается с нарастающей паузой (10→20→40…→120 с). Старты разнесены во времени.
- **Проверка настроек.** Перед запуском конфиг каждого рынка проверяется (`validate_p2p`/`validate_exchange`);
  рынок с ошибкой пропускается с понятным сообщением, остальные работают.
- **Мягкая остановка.** Ctrl+C выставляет всем задачам stop — они выходят из цикла.
- **Логи** — `autobid/logging_setup.py`: консоль + `logs/autobid.log` (с ротацией) и `logs/trades.jsonl` —
  машиночитаемый журнал каждой смены курса (ТЗ §7; из него потом строится «История операций», ТЗ §6).
- **Состояние** — `autobid/state.py`: атомарный JSON в `state/` для работы после перезапуска (ТЗ §5).

## Общие ограничители (ТЗ §3–4, §7)

Настраиваются на каждый рынок (см. `config.example.py`), реализованы в `outbid.py` как чистые функции:

- **Коридор** `initial` + `max_dev_pct` (фикс) / `initial_ratio` + `max_dev_pp` (плав).
- **Поведение у края коридора** `on_limit`: `"reset"` (вернуться к исходному курсу — текст ТЗ) или
  `"hold"` (встать на границу коридора и держать место) — `corridor_bound`.
- **Абсолютные пределы** `min_price` / `max_price` — `clamp_price`, бот не выходит за них никогда.
- **Защита от аномалий** `max_jump` — не прыгать больше, чем на столько, за одну правку.
- **Предел числа перебиваний** `max_changes` — после него объявление не трогаем.
- **Защита от «дёрганья»** `stability_polls` — конкурент засчитывается, только если держится N опросов
  (`StabilityGuard`, применяется в живом цикле `P2POutbidder.step_once`).
- **Частота правок** `cooldown_changes` / `cooldown_min` — `CooldownGuard`.
