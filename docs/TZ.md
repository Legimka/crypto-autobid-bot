Текст ТЗ получен 02.11.2026. Ниже он приведён без изменений, затем идут дополнения заказчика и выводы анализа.

## Дополнения заказчика (03.11.2026)

- Нужны **и P2P-маркет, и торговля на бирже** с автоперебивкой.
- **На обеих площадках:** и в CryptoBot (кнопки «P2P» и «Биржа» в меню бота), и в xRocket.
- Для изучения ботов доступен тестовый аккаунт Telegram. Действия с объявлениями записываются рекордером на
  основном аккаунте и затем воспроизводятся ботом.

## Выводы анализа

**Что есть в API площадок:**

| Что нужно | CryptoBot | xRocket |
|---|---|---|
| Биржа: стакан, создание и отмена заявок, баланс | публичного API нет; «Биржа» — мини-приложение, нужна запись (`record_webapp.py`) | официальный Exchange API: REST + WebSocket, есть testnet |
| P2P: стакан, свои объявления, смена цены | публичного API нет; внутреннее API мини-приложения уже изучено в cryptobot-p2p-bot (`GET /p2p/offers`, `PATCH /p2p/offers/{id}`) | публичного API для объявлений не найдено; нужна запись |
| Crypto Pay API / xRocket Pay API | только платежи: счета, чеки, переводы | только платежи |

Требование «только через API, без Mini App и эмуляции нажатий» для CryptoBot и P2P xRocket невыполнимо
буквально. Реалистичный вариант: запросы к внутреннему API мини-приложения, без кликов. Вход в это API всё равно
требует сессии Telegram (initData), поэтому без аккаунта Telegram не обойтись.

**Логика перебивания (что уточнить или добавить):**

1. **Возврат к начальному курсу у предела зацикливается.** Бот вернулся к начальному курсу, перестал быть первым
   и сразу начинает перебивать снова — получается «пила». Варианты: стоять на границе; вернуться и сделать паузу;
   встать вторым.
2. **Нет «подтягивания».** Если конкурент ушёл, цену нужно вернуть к уровню «следующий конкурент ± шаг».
3. **Бот не должен перебивать сам себя.** На P2P свои объявления узнаются по нику. В биржевом стакане видны
   только уровни цен, поэтому свой объём нужно вычитать из уровня.
4. **Биржа: нельзя пересекать спред.** Иначе заявка исполнится сразу как рыночная, с комиссией тейкера.
   Нужны лимиты позиции и аварийная кнопка «снять всё».
5. **P2P: конкурент — только объявление с тем же минимальным лимитом** (правило из cryptobot-p2p-bot).
6. **Плавающая цена** (у монет почти всегда): коридор нужно задавать в процентных пунктах от биржевого курса.
7. **Защита от «дёрганья».** Конкурент учитывается, только если продержался 2 опроса. Нужен лимит смен цены
   в минуту и учёт `price_next_change_at` у CryptoBot.
8. **Перезапуск.** При старте сверять заявки на площадке с базой и отменять лишние.

**Риски:**
- Автоперебивка 24/7 делает основной аккаунт заметным для CryptoBot. Раньше курс менялся только по кнопке человека.
- Внутренние API меняются без предупреждения.
- Токен xRocket даёт полный доступ к аккаунту.

**Вопросы заказчику:**
- поведение у границы коридора;
- нужно ли подтягивание;
- коридор для плавающей цены;
- лимит позиции и дневной стоп по убытку;
- где будет работать бот (ПК или VPS);
- допустимая заметность (частота смен цены).

## Текст ТЗ

ТЕХНИЧЕСКОЕ ЗАДАНИЕ: Telegram-бот для автоматического P2P-обмена криптовалюты

### 1. Основная задача

Разработать Telegram-бота для автоматической торговли криптовалютой через стакан заявок CryptoBot и/или xRocket.

Бот должен автоматически отслеживать предложения других пользователей и постоянно корректировать мои заявки, чтобы они занимали первое место в стакане.

Принцип работы — аналог сатошкиного бота с автоматическим перебиванием заявок, но с гибкими настройками и собственными ценовыми ограничениями.

Важно: бот должен работать через API CryptoBot или xRocket напрямую, а не через Telegram Mini App, браузерную автоматизацию или эмуляцию нажатий.

### 2. Логика перебивания заявок

Бот должен уметь автоматически работать с двумя направлениями: ПОКУПКА и ПРОДАЖА.

**Продажа криптовалюты**

Чтобы моя заявка находилась выше остальных в списке выгодных предложений, бот должен выставлять цену немного ниже ближайшего конкурента.

Пример:

- Конкурент продаёт по 1.1500.
- Я выставляю по 1.1499.
- Другой конкурент перебивает меня и выставляет 1.1498.
- Мой бот обнаруживает изменение и выставляет 1.1497.

Таким образом бот постоянно старается удерживать мою заявку на первом месте.

**Покупка криптовалюты**

Здесь логика обратная: бот должен выставлять цену немного выше конкурентов.

Пример:

- Конкурент покупает по 1.1500.
- Я выставляю по 1.1501.
- Другой конкурент перебивает меня и выставляет 1.1502.
- Мой бот обнаруживает это и выставляет 1.1503.

Таким образом бот старается постоянно удерживать первое место и в разделе покупки.

### 3. Гибкие ценовые ограничения (ОБЯЗАТЕЛЬНО)

Это одна из самых важных функций.

Я должен самостоятельно задавать первоначальный курс и максимальный диапазон, в пределах которого бот имеет право перебивать конкурентов.

Например:

- Начальный курс: 1.1500.
- Максимальный диапазон изменения: 2%.
- Шаг перебивания: 0.0001.

Бот начинает перебивать конкурентов, постепенно изменяя цену.

Принцип работы ограничения 2%:

Если цена доходит до установленного предела в 2% относительно первоначального курса, бот прекращает дальнейшее перебивание и возвращает мою заявку к первоначальному курсу — 1.1500.

После возврата бот продолжает мониторить стакан и работает в рамках заданных ограничений.

Важно, чтобы это работало корректно как для покупки, так и для продажи, с учётом противоположного направления изменения цены.

Процент ограничения должен настраиваться вручную: например, 0.5%, 1%, 2%, 3%, 5% или любое другое значение.

### 4. Настройки автоматического перебивания

Необходимо предусмотреть возможность гибкой настройки:

- Начальный курс.
- Шаг перебивания.
- Максимальное отклонение от начального курса в процентах.
- Минимальный и максимальный курс.
- Максимальное количество перебиваний.
- Максимальный объём заявки.
- Минимальный объём заявки.
- Отдельные настройки для покупки.
- Отдельные настройки для продажи.
- Возможность включать и выключать автоматическое перебивание.

Все ограничения должны соблюдаться строго. Бот не должен выходить за установленные ценовые пределы.

### 5. Работа с несколькими заявками

Бот должен уметь:

- Отслеживать мои активные заявки.
- Автоматически менять цену существующих заявок, если API это поддерживает.
- Если изменение невозможно — отменять старую и создавать новую.
- Не создавать дублирующие заявки.
- Контролировать актуальное состояние каждой заявки.
- Поддерживать автоматическую работу после перезапуска.

### 6. Интерфейс Telegram-бота

Главное меню:

- 📊 Баланс
- 🔄 Автоматический обмен
- 📈 Мониторинг стакана
- 🛒 Автоматическая покупка
- 💰 Автоматическая продажа
- ⚙️ Настройки
- 📋 Мои заявки
- 📜 История операций
- ⛔ Остановить бота

В интерфейсе необходимо отображать:

- Мой текущий курс.
- Лучший курс конкурента.
- Мою позицию в стакане.
- Первоначальный курс.
- Текущий процент отклонения.
- Установленный максимальный процент.
- Статус автоматического режима.

### 7. Технические требования

- Прямая работа через API CryptoBot и/или xRocket.
- Работа без Telegram Mini App.
- Работа 24/7 в фоновом режиме.
- Максимально быстрая реакция на изменение стакана.
- Использование WebSocket при наличии такой возможности.
- Надёжное хранение настроек и состояния заявок.
- Защита API-ключей и данных пользователя.
- Логирование всех изменений курса и действий бота.

### 8. Проверка API перед разработкой

До начала разработки необходимо проверить, поддерживают ли API выбранной платформы:

- Получение актуального стакана заявок.
- Создание заявок на покупку и продажу.
- Изменение цены существующих заявок.
- Отмену заявок.
- Получение баланса.
- Получение статуса заявок.

Если нужных методов нет, необходимо сообщить об этом и предложить технически возможный вариант реализации.

### 9. Итоговая цель

Мне нужен полноценный автоматический Telegram-бот, работающий по принципу сатошкиного бота.

Он должен самостоятельно следить за конкурентами, перебивать их в правильном направлении, удерживать первое место в стакане и автоматически возвращаться к первоначальному курсу при достижении установленного процентного лимита.

При этом я должен иметь полный контроль над всеми настройками, лимитами и направлениями торговли.

**Дополнение заказчика:** я бы добавил защиту от ситуации, когда конкуренты выставляют аномальные цены или быстро меняют заявки туда-сюда. Бот должен проверять актуальность стакана перед каждым изменением, чтобы не совершать лишние операции и не тратить деньги на комиссии.
